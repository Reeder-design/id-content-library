# Library Item Template

Each library item owns one folder at `items/<slug>/`.

```text
items/<slug>/
├── item.json
├── index.html   # generated permanent public item page
├── preview/     # optional browser-viewable or launchable output
├── source/      # optional reusable/downloadable source files
└── assets/      # optional thumbnail, screenshots, or supporting media
```

Only `item.json` is authored as required metadata. `index.html` is generated by `python scripts/build-library.py`; do not hand-edit it. The other folders are created only when the item needs them.

## Source of truth

`items/<slug>/item.json` is the canonical metadata source for a published item. The build script regenerates both `library-data/items.json` and each item's permanent `index.html` from those item folders.

## Required metadata

`title`, `slug`, `summary`, `content_type`, `format`, `tools`, `tags`, `library_status`, `preview_type`, and `created`.

## Optional metadata

`updated`, `portfolio_status`, `thumbnail`, `other_label`, and `usage_notes`.

The canonical schema is `library-data/item-schema.json`. Controlled choices and future Library Manager dropdown values live in `library-data/options.json`.

## Other behavior

When `content_type`, `library_status`, `preview_type`, or `portfolio_status` is set to its `Other`/`other` choice, `other_label` is required and should briefly describe the custom value.

## Folder conventions

- `preview/` contains files intended to be viewed or launched from the public Lab.
- Interactive web output may use `preview/index.html`, `preview/story.html`, `preview/index.htm`, or another top-level HTML launch file. Standard Storyline `story.html` output is supported directly.
- PDF previews are embedded in the item page when possible. Other document formats get a direct open link.
- Image and video previews are embedded when a supported file exists.
- Text/code previews render safely as escaped text and are truncated after 40,000 characters.
- `source/` contains reusable source files and produces download links on the item page.
- `assets/` contains thumbnails, screenshots, and supporting media used by the item page or card.
- Folder presence can inform the UI, but an empty folder is never treated as a usable preview or download.
- Unsupported or incomplete preview packages degrade to a clear open/download or no-preview message instead of breaking the page.

Do not place confidential, proprietary, credential-bearing, or otherwise non-public-safe material in any item folder.
